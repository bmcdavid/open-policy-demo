# Learning Lab: Kubernetes + Argo CD + Policy Sidecars

Date: 2026-10-23. Supersedes the earlier draft in `docs/DESIGN.md`.

## Goal

Learn Kubernetes operations through GitOps with Argo CD by deploying this repo's .NET authorization demo (Api with OPA and Cedar sidecars, Worker, Keycloak, Cosmos DB, RabbitMQ, Valkey) to a local kind cluster, with cluster guardrails from OPA Gatekeeper.

Git is the source of truth. Bootstrap is the only imperative step.

## Non-goals

- Production hardening, HA, cloud cost.
- CI pipelines (stretch phase only).
- Replacing Aspire. `dotnet run --project src/AppHost` stays the inner loop and must behave exactly as today.

## Decisions

| # | Topic | Decision |
|---|---|---|
| 1 | Scope | Shared backing services in an `infra` namespace. Api + OPA + Cedar + Worker per env namespace (`app-dev`, `app-staging`, `app-prod`). |
| 2 | Environment semantics | Each deployment has an allowlist for `X-Environment`: dev `[dev, staging, prod]`, staging `[staging, prod]`, prod `[prod]`. A value outside the list is 400. |
| 3 | Missing header | Defaults to the deployment's own environment when `Deployment:DefaultEnvironment` is set; otherwise 400 (today's behaviour). |
| 4 | Env isolation | RabbitMQ vhost per env, Valkey DB index per env (dev 0, staging 1, prod 2), Cosmos database per env via a configurable `Cosmos:Database`. |
| 5 | Keycloak issuer | CoreDNS rewrites `keycloak.localtest.me` to the Envoy Gateway Service, so laptop and pods use one URL. `KC_HOSTNAME=http://keycloak.localtest.me`. `Auth:RequireHttpsMetadata` becomes an explicit setting. |
| 6 | Policy delivery | Policies are versioned artifacts. OPA: `opa test`, then `opa build`, pushed to `localhost:5001` as an OCI bundle. Cedar: `policies.json` generated by `src/CedarPolicyTool` and baked into a thin `cedar-agent` image. Both tagged with the git short SHA; overlays pin the tags. |
| 7 | Policy engine | Both sidecars in every pod. `POLICY_ENGINE` set per overlay: dev `opa`, staging `cedar`, prod `opa`. |
| 8 | Gatekeeper scope | Tiered by namespace label `lab.dev/tier` (see Gatekeeper). |
| 9 | Secrets | SOPS + age, decrypted in Argo by KSOPS. The age key stays on the laptop; bootstrap seeds it as a Secret. |
| 10 | Repo layout | `deploy/` folder in this repo. Argo watches only `deploy/**`. |
| 11 | Repo access | The repo is made public; Argo pulls anonymously, no deploy key. |
| 12 | Promotion | All Applications track one branch. Promotion is a commit that copies tags from the staging overlay to the prod overlay, followed by a manual sync of prod. Argo tracks `k8s` until it merges, then `main`. |
| 13 | Cosmos emulator | **vNext preview** (`mcr.microsoft.com/cosmosdb/linux/azure-cosmos-emulator:vnext-preview@sha256:db53613dae19d0a3d5ad50688d14aa6e957af082dafea56b52e1bd3a6b3f1406`, `--protocol http`). Spike 2026-10-23: `CosmosInitializerService` completed first try, create returned 201 (transactional batch), and the change feed processor with the `leases` container relayed Created/Updated/Deleted to audit within 1 s, with no warnings. |
| 14 | Cluster | kind, 1 control plane + 2 workers. Docker Desktop at 12 GB (14-16 GB if the classic emulator is chosen). Never run alongside `aspire run` (ports 8080, 8181, 8180 and memory). |
| 15 | Ingress | Gateway API with Envoy Gateway (ingress-nginx was retired in March 2026). |
| 16 | Observability | Standalone Aspire Dashboard in `infra`, receiving OTLP from every app pod. |
| 17 | Verification | One E2E fixture with two targets. `E2E_TARGET=k8s` uses URLs from env vars instead of starting Aspire. Tests that need the sidecars or the broker directly are trait-filtered out in k8s mode. |

Hostnames: `api.dev.localtest.me`, `api.staging.localtest.me`, `api.prod.localtest.me`, `keycloak.localtest.me`, `dashboard.localtest.me`. The Envoy proxy Service has the fixed name `envoy-lab` (set through an `EnvoyProxy` resource) and type NodePort 30080/30443, which kind maps to host ports 80 and 443. The CoreDNS rewrite targets `envoy-lab.envoy-gateway-system.svc.cluster.local`.

## Architecture

```
 Laptop (Docker Desktop)
 ├── kind: 1 control-plane + 2 workers, host :80/:443 -> Envoy Gateway
 │   ├── argocd ............ Argo CD + KSOPS (age key Secret seeded by bootstrap)
 │   ├── gatekeeper-system . Gatekeeper
 │   ├── envoy-gateway-system  Envoy Gateway + shared Gateway "lab" (*.localtest.me)
 │   ├── infra ............. keycloak | cosmos | rabbitmq (vhosts dev/staging/prod)
 │   │                       | valkey (db 0/1/2) | aspire-dashboard
 │   ├── app-dev ........... api pod [opa, cedar (native sidecars) | api] + worker pod
 │   ├── app-staging ....... same
 │   └── app-prod .......... same, api replicas: 2
 ├── registry:2 at localhost:5001 (joined to the kind network)
 │     images: api, worker, cedar-policies    OCI artifact: opa-bundle
 └── CoreDNS: rewrite keycloak.localtest.me -> Envoy Gateway Service
```

Request path: laptop → `api.<env>.localtest.me` → Gateway → `HTTPRoute` in `app-<env>` → api container → OPA or Cedar on `localhost` → Cosmos, Valkey, RabbitMQ in `infra` via cluster DNS.

Token path: laptop and api pod both use `http://keycloak.localtest.me/realms/opa-demo`. On the laptop the name resolves to 127.0.0.1 (kind port mapping); in the cluster CoreDNS rewrites it. The issuer therefore matches by construction.

Two policy layers stay separate:
- Gatekeeper: is this manifest allowed into the cluster? (admission time)
- OPA/Cedar sidecars: is this user allowed to make this API call? (request time)

## Code changes

Every change defaults to today's behaviour when unset, so Aspire runs unchanged.

1. **Environment allowlist.** `Deployment:AllowedEnvironments` (list; default dev, staging, prod) and `Deployment:DefaultEnvironment` (default unset). The section is `Deployment`, not `Environment`, because `ASPNETCORE_ENVIRONMENT` already owns the `environment` configuration key. Invalid values fail at startup. A header value outside the list is 400 with reason `environment not allowed in this deployment`. A missing header uses `Deployment:DefaultEnvironment` when set, otherwise 400 as today.
2. **Cosmos database name.** `Cosmos:Database` (default `policy-demo`) replaces the `CosmosNames.Database` constant at every call site.
3. **HTTPS metadata.** `Auth:RequireHttpsMetadata` (default `!IsDevelopment()`, as today).
4. **CedarPolicyTool.** A new console project. `src/AppHost/Cedar/*` moves into it. `generate <authz.cedar> <policies.json>` writes the file or exits non-zero with the existing line-numbered errors. AppHost references it with `IsAspireProjectResource="false"` and keeps calling `CedarPolicyGeneration.Generate` in-process. `InternalsVisibleTo("Tests")` keeps the existing Cedar tests working.
5. **E2E fixture k8s mode.** `AppHostFixture.InitializeAsync` reads `E2E_TARGET`. When it is `k8s`, it sets `KeycloakUri` and `ApiClient` from `E2E_KEYCLOAK_URL` and `E2E_API_URL` and does not start Aspire. Tests that use `OpaUri`, `CedarUri` or `GetConnectionStringAsync` get `[Trait("Target", "aspire-only")]`.

## Api pod

```yaml
initContainers:                       # native sidecars: start first, stop last
  - name: opa
    image: localhost:5001/opa:<pinned>   # mirrored: app-* may only pull from localhost:5001
    restartPolicy: Always
    args: [run, --server, --addr=127.0.0.1:8181, --config-file=/config/opa-config.yaml]
    readinessProbe: { httpGet: { path: /health?bundles, port: 8181 } }
  - name: cedar
    image: localhost:5001/cedar-policies:<sha>
    restartPolicy: Always
    env: CEDAR_AGENT_ADDR=127.0.0.1, CEDAR_AGENT_PORT=8180, CEDAR_AGENT_POLICIES=/config/policies.json
    readinessProbe: { tcpSocket: { port: 8180 } }
containers:
  - name: api
    image: localhost:5001/api:<sha>
    env: Opa__BaseAddress=http://localhost:8181, Cedar__BaseAddress=http://localhost:8180,
         POLICY_ENGINE, Deployment__AllowedEnvironments__*, Deployment__DefaultEnvironment, Cosmos__Database,
         Auth__Authority, Auth__Audience, Auth__RequireHttpsMetadata, OTEL_EXPORTER_OTLP_ENDPOINT,
         ConnectionStrings__* (from SOPS secret)
    readinessProbe: { httpGet: { path: /buildinfo, port: 8080 } }
```

- The sidecars bind to `127.0.0.1`, so only containers in the pod can reach them.
- Each overlay's `opa-config.yaml` comes from a `configMapGenerator` (hashed name, so a change rolls the pods). It points an OCI service at `http://kind-registry:5000` (the registry's name on the `kind` Docker network; `localhost:5001` only works for image pulls through the containerd mirror) with `resource: opa-bundle:<sha>`.
- **Checked in Phase 4 (2026-10-23): the OCI path works, no fallback needed.** OPA 1.21.4 on the `kind` network loaded `opa-bundle:<tag>` from `http://kind-registry:5000` (service `type: oci`, bundle `resource: kind-registry:5000/opa-bundle:<tag>`, `persist: false`); `/health?bundles` returned 200 and decisions came from the bundle.
- All images use explicit tags: `opa`, `cedar-agent` and every infra image. No `:latest` in `deploy/`.
- The Worker is a separate Deployment, one replica per env, sharing its env's Cosmos database, vhost and Valkey index. No sidecars.

## Platform and infra

### Bootstrap (the only imperative step, idempotent)

1. `registry.sh`: start `registry:2` on port 5001 and connect it to the `kind` network.
2. `kind create cluster --config kind-config.yaml`: 3 nodes, host ports 80 and 443, containerd mirror for `localhost:5001`.
3. Apply `coredns-patch.yaml` (the `keycloak.localtest.me` rewrite). Kept in Git but applied here, because Argo cannot cleanly adopt the `kube-system` CoreDNS ConfigMap.
4. `build-images.sh` and `build-policies.sh`: push the first tags.
5. `argocd-install.sh`: install Argo with KSOPS (Helm values in Git), create the `sops-age` Secret from `~/.config/sops/age/keys.txt`, apply `root-app.yaml`.

### Argo CD

- App of apps: `root-app.yaml` points at `deploy/argocd/apps/`.
- Sync waves: `-3` Envoy Gateway, Gatekeeper → `-2` Gateway, ConstraintTemplates → `-1` Constraints, infra → `0` app envs.
- dev and staging: automated sync with self-heal and prune. prod: manual sync.
- `ServerSideApply=true` on Applications that install CRDs (Gatekeeper, Envoy Gateway). `SkipDryRunOnMissingResource=true` on Constraints. `ignoreDifferences` for fields Gatekeeper writes.
- `targetRevision: k8s` until the PR merges, then `main`.
- Platform components (Argo, Gatekeeper, Envoy Gateway) are Helm charts rendered by Argo. Infra services are hand-written manifests.

### Secrets

`.sops.yaml` encrypts `data` and `stringData` in `deploy/**/secrets/*.sops.yaml` with the age public key. Contents: Cosmos key, a RabbitMQ user per vhost, Keycloak admin credentials, per-env connection strings. KSOPS decrypts during the Argo render. Decrypted files are never committed.

### Infra services (`infra` namespace)

- **Keycloak:** Deployment, `start-dev`, realm imported from a ConfigMap built from the existing realm JSON with redirect URIs added for the new hostnames. `KC_HOSTNAME=http://keycloak.localtest.me`. Ephemeral H2; the realm is re-imported on every start.
- **Cosmos:** Deployment, image chosen in Phase 0, `startupProbe` with a long budget. The Api and Worker create the database and containers on startup through `CosmosSetup.EnsureCreatedAsync`. Classic emulator only: `AZURE_COSMOS_EMULATOR_IP_ADDRESS_OVERRIDE` set to the Service address and `DisableServerCertificateValidation=True` in the connection string (demo only).
- **RabbitMQ:** StatefulSet with a PVC. Vhosts `dev`, `staging`, `prod` and one user per vhost from a definitions file.
- **Valkey:** Deployment, no persistence.
- **Aspire Dashboard:** Deployment with an OTLP gRPC Service, exposed at `dashboard.localtest.me`, unauthenticated (marked as such with its env var).

### Gatekeeper

Every namespace carries `lab.dev/tier: platform | infra | app`. Constraints match on it.

| Constraint | platform | infra | app-* |
|---|---|---|---|
| CPU/memory requests and limits | – | ✓ | ✓ |
| No `:latest` or untagged images | – | ✓ | ✓ |
| Images only from `localhost:5001/*` | – | – | ✓ |
| Labels `app.kubernetes.io/name`, `owner` | – | ✓ | ✓ |
| `replicas >= 2` | – | – | `app-prod` only |

Templates are taken from the upstream `gatekeeper-library` and copied into the repo. They must check `spec.initContainers` as well as `spec.containers`, because the native sidecars are init containers. Each constraint has a passing and a failing fixture under `gatekeeper-policies/tests/` for `gator verify`.

## Failure modes

| Failure | Expected behaviour |
|---|---|
| `opa test` fails in `build-policies.sh` | Nothing is pushed; the overlay keeps its tag. |
| Invalid `authz.cedar` | CedarPolicyTool exits non-zero with line numbers; no image is built. |
| OPA cannot fetch its bundle | `/health?bundles` fails, the new pod is never Ready, the old ReplicaSet keeps serving. |
| Cosmos still starting | Api readiness fails until Cosmos answers; no crash loop. **Check in Phase 3:** `CosmosInitializerService` retries; fix it if it does not. |
| Manifest violates a constraint | Argo shows a sync error with the constraint message; live state is unchanged. |
| Hand edit in dev or staging | Self-heal reverts it. Prod shows OutOfSync and is left alone. |
| Cluster rebuilt | Bootstrap re-seeds the age key and Argo re-syncs. Keycloak re-imports the realm. Cosmos and RabbitMQ data is lost (expected). |

## Testing

- **Unit (`tests/Tests`):** the allowlist (out-of-list value is 400; missing header uses `Deployment:DefaultEnvironment` only when set), `Cosmos:Database` wiring, `Auth:RequireHttpsMetadata` default. Existing Cedar tests now target CedarPolicyTool.
- **E2E:** the Aspire target runs everything, as today. The k8s target runs `E2E_TARGET=k8s dotnet test --project tests/Tests --filter-namespace "Tests.E2E" --filter-not-trait "Target=aspire-only"` against dev (xunit v3 on Microsoft.Testing.Platform). Tests must tolerate data left by earlier runs (unique ids per run); check and fix during Phase 5.
- **Policy:** `opa test` and Cedar validation inside `build-policies.sh`.
- **Manifests:** `validate.sh` runs `kustomize build` on every overlay and `gator verify` on the Gatekeeper fixtures. Run before pushing.

## Phases

Each phase ends with something observable.

0. **Cosmos spike (throwaway).** Run the vNext preview emulator in Docker and point the Worker's change feed processor and the Api's transactional batch at it. *Done when:* a written verdict picks vNext or classic. Spike code is deleted.
1. **Cluster, registry, DNS.** *Done when:* `kubectl get nodes` shows 3 Ready, an image pulls from `localhost:5001`, and the CoreDNS rewrite is in place. Re-running bootstrap is a no-op.
2. **Argo, SOPS, app of apps, Gateway.** *Done when:* the root app is Synced and Healthy, a SOPS secret is decrypted in the cluster, a hand-deleted managed resource is recreated, the Gateway reports Programmed, and a test pod resolves `keycloak.localtest.me` to the Gateway Service. (Envoy Gateway is installed by Argo, so the DNS check moves here.)
3. **Infra.** *Done when:* every `infra` pod is Ready, a token is minted from the laptop through `keycloak.localtest.me`, and the dashboard loads.
4. **Code changes and policy artifacts.** *Done when:* unit tests pass, `build-policies.sh` pushes the OPA bundle and the cedar-policies image, a deliberately failing Rego test blocks the push, and OPA's OCI loading from `localhost:5001` is confirmed (or the fallback is in place).
5. **App in dev.** *Done when:* the k8s E2E command above passes against `api.dev.localtest.me`, and one request's trace is visible in the dashboard.
6. **Gatekeeper.** *Done when:* committing a `:latest` image or a container without limits fails the sync with the Gatekeeper message, and `gator verify` passes.
7. **Staging, prod, promotion.** *Done when:* a Cedar policy change, rebuilt with a new tag, reaches dev automatically and staging after its tag bump, and reaches prod only after the promotion commit and a manual sync.
8. **Stretch.** ApplicationSets for envs, Argo projects and RBAC, Argo Rollouts, NetworkPolicies, GHCR with GitHub Actions, Argo CD Image Updater.

## ECS to Kubernetes reference

| ECS | Kubernetes |
|---|---|
| Cluster | Cluster (here: kind nodes are Docker containers) |
| Task definition | Pod spec (inside a Deployment) |
| Sidecar containers in a task | Native sidecars (`initContainers` with `restartPolicy: Always`) in one Pod, sharing localhost |
| Service | Deployment (keeps N pods running) + Service (stable network name) |
| ALB + target group | Gateway + HTTPRoute + Service |
| CodePipeline/CodeDeploy push | Argo CD pull: the cluster reconciles itself to Git |
| Task role / IAM | ServiceAccount + RBAC |
| Secrets Manager | Secret (here: SOPS-encrypted in Git, decrypted by KSOPS) |
